## The common failure mode

**Two NPDM values driving everything.** Three of the day's most painful regressions (R0, R1a, R1b) are all the *same root cause*: `system_resource_size` and `main_thread_stack_size` in `uSystem.json` were treated as if they had a single correct value when they actually have a *binary-size-dependent* correct value. Yesterday's fix (revert to `0x0/0x80000`) traded one regression for two more (Hekate dies, login screen stutters) because no agent ran the math against the *current* BSS footprint. Today's fix (revert back to `0xC00000/0x100000`) will reintroduce R0's `am 2001-0132` panic if the v2.x BSS isn't first reduced. **The values needed depend on what the binary contains, but the agents fixing each regression were treating them as constants.**

**Underneath that: every regression in the table is a state-machine + integration coupling that was changed without rerunning the OPPOSITE-direction tests.** R4 (Album hijack) broke Hekate reboot 3 times because nobody ran a Hekate test after each Album fix. R5 (`Finalize()` kills uMenu) shipped because nobody simulated an SMI failure path. R2 (`nxlinkConnectToHost` on main thread) shipped because nobody clicked the new login button after wiring it. R6 (sidebar drag) shipped a fix in the same diff as the bug. **Pattern: changes are validated against the goal they were made for, never against what they could break.** The `[HW-GREEN]` tag on commits `2ab5fa30` and `dd0a3a31` was applied without running a regression matrix — the deployed binary md5s don't even match the commits (per `SESSION-REGRESSION-AUDIT`).

## Recurring vs novel

**Recurring (the real signal):**
- **Login screen reactivity** — R1b, R2, R3, prior 2 rounds. Documented in `feedback_login_screen_no_regress.md`. The memory protected `qd_PowerButton.cpp` invariants (intact in source today!) but did not protect against starvation-via-NPDM (R1b), main-thread-blocking-via-DevTools (R2), or per-frame-SetText (R3). **Memory's scope was too narrow** — protected the *buttons* but not the *frame budget* the buttons depend on.
- **NPDM budget mismatch** — R0 mirrors the Apr 26 cycle per `MTIME-ARCHAEOLOGY`. Same mistake, same fix, same agents.
- **Album hijack** — R4 cycled 5 times in one day; per dirty-tree comment "three independent hardware confirmations of the same regression."
- **Finalize-after-applet-launch** — R5 was already flagged as `S1` in `SESSION-REGRESSION-AUDIT` and is still in the dirty tree.

**Novel:** R1a (the specific NPDM-revert × new-SMI-handler interaction), R6 (sidebar drag), SC1 (file picker scope creep).

The recurring ones reveal the failure mode: **fixing the symptom of last regression introduces the next one because no one runs the opposite test.**
